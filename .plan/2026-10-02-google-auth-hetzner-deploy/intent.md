# Intent

Goal: Sonar can run safely on a real domain: only Google accounts on an allow-list stored in the database get in, it deploys with terraform onto the owner's existing Gateway Hetzner VM behind Cloudflare, and two pre-deploy fixes land first: one instruction file for every agent, and loans that come from fixed payments.

In scope: AGENTS.md as the single instruction source with CLAUDE.md a one-line `@AGENTS.md` pointer and every reference updated; optional Google OIDC login (on only when its settings are present) with a signed-cookie session, an `allowed_emails` table, a not-allowed page, logout, a bearer token for `/api/*`, and `sonar allow-email`, `revoke-email`, `list-emails`, `sync-emails`; env-configurable DB path and port with proxy-header support; a `debt` flag on categories (migration, Categories page, API, AGENTS.md table) and draft debts created idempotently from recurring payments in flagged categories, shown as "needs details" with a completion form; SPEC §0/§13 amendments for auth, the flag and drafts; a `deploy/terraform/` root module that finds the Gateway VM, adds a protected Hetzner volume, installs Sonar over SSH with systemd and an nginx server block, adds a proxied Cloudflare record and syncs allowed emails on every apply; `deploy/README.md` with the Google Cloud setup, the Gateway nginx patch, the deploy and the one-time DB upload; owner gates for Google setup and the real deploy.

Out of scope: roles or permissions, per-user data, backups or automated DB sync, CI/CD, changes to the Gateway repo (the owner applies the one-line patch), a dedicated VM, Docker, zone-wide Cloudflare settings.

Constraints: AGENTS.md engineering rules: strict TDD, functional core with `today` as a parameter, `store.py` the only DB access, page routes in `web/pages/`, `tests/test_architecture.py` green, applied migrations never edited, money in cents. Tests never touch the network (Google is faked). No real names, IBANs, domains, emails or tokens in tracked files; terraform uses example.com placeholders and secrets live only in gitignored `terraform.tfvars` and local state. With no auth settings `uv run sonar` behaves exactly as today. Hand-entered debts and schedules survive upgrades and re-detection; a payment is never counted twice. sonar.css is rebuilt and committed after template changes; template changes get a visual check; the last node checks SPEC §11, §12 and the new amendments. Each node commit is pushed to claude/youthful-thompson-0snams; agents never push main, the owner merges it into main before the deploy. Decisions D1-D24 in plan.md.

Definition of done: the full verify passes; without auth settings the app is unchanged; tests show an unauthenticated redirect to sign-in, an allowed email getting in, a non-listed or unverified one refused, the API bearer token accepted and a wrong one rejected; the four email commands are tested; the debt flag and draft debts are tested and visible on their pages; `terraform fmt -check` and `terraform validate` pass (or the gap is documented); deploy/README.md takes the owner from an empty Google Cloud project to a running deploy; the owner confirms login on the real domain.
