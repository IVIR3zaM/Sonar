  D13: table `debt_drafts(id INTEGER PRIMARY KEY, detection_key TEXT NOT NULL UNIQUE, status TEXT NOT NULL DEFAULT 'open' CHECK (status IN ('open', 'completed')))`, nothing else: an open draft holds no hand data, its prefill is computed on read. A payment qualifies when it is active, has a detection key and its category is debt-flagged, and no stored debt links to it yet (the key is not in any debt's `linked_keys`, src/sonar/debts/model.py:218, as `debt_overview` does at src/sonar/debts/store.py:52): an owner's hand-entered debt already holds its details, and a payment is never shown twice.
  `sync_drafts(conn) -> list[DebtDraft]` in one transaction: insert an open row for each qualifying key without a row, delete open rows whose key no longer qualifies (completed rows are never touched), then return the open drafts (`id`, `detection_key`, prefill) ordered by name. It is idempotent: a second call changes nothing and keeps the ids. Flagged names come from `sonar.categorization.store.list_categories` (`.debt`, src/sonar/categorization/store.py:130); payments from `list_payments` (src/sonar/recurring/store.py:43, active only); transactions from `transactions_with_category`.
  `complete_draft(conn, draft_id, debt: Installment | Loan) -> int` inserts the debt through the existing model and insert (src/sonar/debts/store.py:91) and marks the draft `completed` in the same transaction (factor the INSERT so it does not commit on its own); an unknown or already completed id raises `DraftNotFound` (LookupError, like `DebtNotFound`) and writes nothing. A completed key never gets a draft again, even after that debt is deleted.
  D14 prefill (frozen dataclass in drafts.py, pure, no sqlite, no `date.today()`): name = payment name; rate_cents = the latest schedule period's amount (periods ordered by starts_on, so `periods[-1]`; honors owner edits); interval_months = that period's interval; first_payment_date = the earliest matching debit's booking date; match = `MatchRule("mandate", <latest matching debit's mandate_ref>)` for `mandate:` keys, else `MatchRule("counterparty", <latest matching debit's counterparty>)`. Matching debit = amount < 0 and `payment_key(tx) == detection_key` (src/sonar/recurring/detect.py:55). A payment with no matching debit gets no draft. Debts keep their two match fields (no debts table rebuild).
