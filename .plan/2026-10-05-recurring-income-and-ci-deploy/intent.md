# Intent

Goal: The cash-flow forecast to payday adds money that arrives regularly besides the salary, such as the monthly child benefit paid around the 15th, and the dashboard shows that money in its own card, labelled by category. Gateway, Sonar and Kita all live on the one Gateway VM. Each of them deploys from the owner's machine or from GitHub Actions, using one shared Terraform state store in Cloudflare R2, and none of them breaks another's access, state or nginx config.

In scope: Sonar forecast: pure detection of recurring credits in `income` categories except the salary series, reusing the outgoing detection rules; each such series forecast from its cadence and latest amount, counted only when a date falls in the window before payday; the projection and expected margin include it; an "Income before payday" dashboard card; a SPEC §13 amendment.
  Deploys: an S3 backend on R2 for Sonar `deploy/terraform`, Kita `deploy/terraform` and Gateway `hetzner/terraform`, one key per project. A label-selector Hetzner firewall per app (`sonar-ssh`, as Kita's `kita-ssh`) that opens SSH to the deployer's detected IPv4. Install scripts that tolerate concurrent installs on a fresh VM. Gateway changes so it plans and applies on a runner without leaking credentials into public logs.
  CI: a test-then-deploy workflow in each repo, with pinned actions and secrets as GitHub secrets. Gateway's workflow redeploys Sonar and Kita when it replaced the VM.
  Docs and owner gates: the deploy READMEs, including the coexistence notes; owner gates for committing the existing WIP, R2 and the three state migrations, the GitHub settings and the PAT, the first CI deploys, and a forced Gateway VM replacement followed by the automatic app redeploys.

Out of scope: income types that recurring detection does not find; public holidays; storing or editing income series; Gateway's `aws/` stack; changing the VM type, Gateway's v2ray setup or the apps' install mechanism beyond the lock wait; categorization rules (the owner adds the child-benefit income category through the Categorization workflow).

Constraints: AGENTS.md rules in Sonar: strict TDD, a functional core with `today` as a parameter, integer cents, migrations never edited, page tests on hooks, the CSS rebuilt and committed. Kita's and Gateway's own rules apply to their nodes; their checks are `node --test` and `terraform fmt -check` / `terraform validate`.
  Data and logs: tests use invented names only; no real names, IBANs, hostnames, IDs or secret values go into tracked files or public CI logs. tfstate, tfvars and backend.hcl are never committed. Locally the R2 credentials live only in each root's gitignored backend.hcl, so terraform needs no exports and the owner's other AWS profiles stay untouched (D29).
  Owner-only: credentials, migrations, pushes and dispatches (D12). Nothing is pushed in any repo before the deploy gates (D13). Cross-repo nodes are committed with `git -C` (D15). Every action is pinned by commit SHA (D11).

Definition of done: forecast tests show that income dated before payday raises the projection and income after payday does not; a dashboard page test finds the income card's hooks; the visual gate passes at desktop and 375px, light and dark. All three workflows pass actionlint with SHA-pinned actions, and all three Terraform roots pass `terraform validate` with their R2 backend block. The owner confirms: each repo deployed from a push and from a dispatch; local applies still work in each repo; Gateway plans show no firewall_ids drift; after a forced Gateway VM replacement, Sonar and Kita redeployed automatically and all three serve. The final check passes, including Sonar's SPEC §11 and §12.
